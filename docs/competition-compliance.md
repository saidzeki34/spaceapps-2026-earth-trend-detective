# Competition compliance

**Prepared October 30, 2026. Verify official event terms and your registered Local Event guidance before beginning.**

## Before the event
- [x] Repository and workflow administration only.
- [ ] Confirm team registration and correct Local Event.
- [ ] Confirm the permitted local start time.
- [ ] Do not create competition-specific solution code, data analysis, visualizations, designs, or results in advance.
- [ ] Identify and clear any reusable prior work under applicable rules.

## During the event
- [ ] Build the solution after the official start.
- [ ] Keep an accurate commit history and team attribution.
- [ ] Credit source data, software, models, imagery, AI tooling, and other materials used.
- [ ] Keep secrets and personal information out of Git.

## Submission
- [ ] Verify license compliance and choose an appropriate OSI-approved license for the submitted code.
- [ ] Provide accessible source, documentation, license details, attribution, demo, and required project fields.
- [ ] Submit before the applicable official event/local deadline.

Official sources: [Space Apps 2026](https://www.spaceappschallenge.org/2026/), [legal terms](https://www.spaceappschallenge.org/legal/), [official challenge](https://www.spaceappschallenge.org/2026/challenges/earth-system-trend-detective/).

Official rules supersede this internal checklist.

## Preparation boundary checked 2026-11-13

The [Global Organizing Team's answer](https://github.com/nasa/spaceapps/discussions/1827) permits challenge selection, resource review, topic research and team formation before the event. It prohibits starting the project before Saturday at 09:00 local time. For Oslo, the general start is November 14 at 09:00 CET (08:00 UTC); verify local instructions before starting.

This update contains generic editor/container configuration, documentation connections and research bookmarks/notes only. Treat tooling preparation as a conservative interpretation, not explicit organizer certification. No solution software, schemas, analysis outputs, data processing or deployment has been produced. Do not begin implementation until the official start and a team instruction to begin.

The [organizers' AI guidance](https://github.com/nasa/spaceapps/discussions/1849) requires disclosure of where and how AI was used, including code/data; generated visual/audio materials have additional labeling requirements. Review that guidance before making submission media. At least one NASA data source from the challenge resources is required for Global Awards. NOAA and partner-agency sources should not be mistaken for NASA sources.

Read-only MCP configuration and instructions are useful boundaries, not enforcement against arbitrary shell commands. No automatic tasks or deployment workflows are included.
